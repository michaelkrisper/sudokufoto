# CLAUDE.md

Installable web app: photograph a sudoku and see the solution drawn into the photo.
Grid detection, digit recognition (own small neural net), handwriting separation and
the solver all run in the browser. Vanilla JS ES modules, no framework, no build step,
no runtime dependencies. CI deploys `main` to GitHub Pages
(https://michaelkrisper.github.io/sudokufoto/). Python is only used offline to render
synthetic photos and train the net.

## Commands

```sh
pip install -r tools/requirements.txt   # Pillow + NumPy, needed by the tests
npm ci                                  # only dev dependency: Biome
npm run serve                           # python3 -m http.server 8792
npm run lint                            # Biome (npm run lint:fix applies fixes)
npm test                                # node:test, incl. 16 rendered sudoku photos
npm run check                           # lint + tests
npm run serve & npm run test:e2e        # headless Chrome, expects the app on :8792
node scripts/e2e.mjs <url> [outdir]     # E2E against another URL / screenshot dir
```

- CI (`.github/workflows/ci.yml`, job `check`): installs DejaVu/Liberation/FreeFont/
  Noto fonts, `pip install`, `npm ci`, `npm run lint`, `npm test`, then E2E against
  `python3 -m http.server 8792`. Deploy runs only after all of it passed.
- Without Pillow/NumPy the photo test is skipped, not failed: install them before
  trusting a green local run.
- E2E needs `google-chrome`, Pillow/NumPy, `fc-match` and the Liberation Sans font
  (fixed font, so results match CI). It uses DevTools port 9335: one instance at a time.
- The photo test and E2E create `sudokufoto-*` temp dirs (PGMs, Chrome profile) in
  `$TMPDIR` and do not delete them; clean up after local runs.

Measuring recognition and retraining (see README):

```sh
tools/synth.py OUT --n 100 --turns                # test photos: OUT/*.pgm + cases.json
node tools/eval.mjs OUT --verbose
tools/synth.py - --n 300 --fonts train --seed N | node tools/extract.mjs train-N.bin
tools/synth.py - --n 300 --fonts test | node tools/extract.mjs val.bin
python3 tools/train.py train-*.bin --val val.bin  # rewrites js/model.js
```

## Architecture

Pipeline (`js/read.js` `readSudoku()`, run in `js/worker.js` off the main thread):
`js/detect.js` adaptive threshold -> largest quad on the convex hull, verified by its
line pattern -> homography -> one cut-out per cell -> `js/ocr.js` classifies with the
net in `js/model.js` (576 -> 128 -> 9, int8 weights) -> orientation -> `js/hand.js`
splits print from handwriting -> `js/solver.js` (bitmask backtracking, counts
solutions). `js/app.js` is the UI: live camera with auto capture, review keypad,
solution overlay.

- `js/model.js` is generated by `tools/train.py`; never edit it by hand. It is
  excluded from Biome.
- Training samples are cut out by `tools/extract.mjs` with the app's own
  `js/detect.js`, so training and app see identical crops. Any change to cell
  extraction or `FEAT` invalidates the model: regenerate data and retrain.
- `tools/synth.py` splits fonts by family: `--fonts test` uses families never seen in
  training. Keep validation on unseen families.
- `sw.js`: network-first service worker; offline from the `SHELL` list.

## Conventions

- Biome: 2 spaces, single quotes, semicolons, trailing commas, line width 110.
- UI text German; code, comments, commit messages English. Comments explain the why.
- No runtime dependencies, no OpenCV, no CDN: everything ships from this repo.
- Recognition changes are judged on many synthetic photos (`tools/eval.mjs`), not a
  single image. The CI photo test demands >= 15/16 grids, > 99.5 % cells, >= 13/16
  exact.

## Rules and pitfalls

- Orientation: count reads with confidence >= 0.97 per rotation (`legibility()` in
  `js/read.js`). The mean confidence does not work: an upside-down 6 is a confident 9
  and pencil marks drag the mean down. Always check all four rotations.
- Handwriting is only separated when the printed digits alone give exactly one
  solution (`separate()` in `js/hand.js`); otherwise every digit stays a given and
  suspects are only reported. The solver has the final say.
- Never write training data or synthetic photos into the repo or a small tmpfs:
  1000+ photos are gigabytes. Stream `synth.py -` into `extract.mjs`; generated
  `*.bin`, `*.pgm`, `cases.json` are gitignored and must stay uncommitted.
- Every new app file must be added to `SHELL` in `sw.js` and to the `cp` line of the
  deploy job in `ci.yml`; only those files are published.
- Real photos that failed in the past: curved pages, grid corners cut off. Synthetic
  photos are the only automated regression net; nothing in CI covers real cameras.

## Workflow

- Every change starts with a GitHub issue. Branch `<issue>-<slug>` from `main`,
  open a PR with `Closes #<issue>`. Never push to `main` directly.
- PRs auto-merge (squash) once CI and the "Linked ticket" check pass; drafts are not merged.
- Versions exist only as git tags `vX.Y.Z`. Every merge to `main` tags the next patch;
  never edit version numbers in files. Minor/major releases: Actions -> Release.
- Merging to `main` deploys to GitHub Pages automatically.
- Details: CONTRIBUTING.md.
